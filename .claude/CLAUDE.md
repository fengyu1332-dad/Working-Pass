## 二、逐字段内容标准

### 2.1 `overview` — 专业概述

```
格式: "{专业名}是{门类名}门类下的{重要/特色}专业，{专业描述}，{培养目标}。"
长度: 40-200字
```

**KB 函数规范（最重要）：**

每条 KB overview 函数必须遵循**关键词匹配 → 分类 fallback → 门类兜底**三级链：

```js
overview: (major) => {
  // 第一级：具体关键词匹配（按 specificity 从高到低排列）
  const map = {
    '精准关键词1': '专业描述',
    '精准关键词2': '专业描述',
    // ...按优先级排列：越具体的词越靠前
  };
  for (const [k, v] of Object.entries(map)) {
    if (major.name.includes(k)) return `${major.name}是工学门类下的重要专业，${v}，培养具备工程实践能力和创新精神的技术人才。`;
  }
  // 第二级：门类统一兜底
  return `${major.name}是工学门类下的特色专业，融合现代工程技术和行业需求，培养具备扎实专业知识和工程实践能力的应用型技术人才。`;
}
```

**关键词编写规则：**
- 用 `includes()` 做子串匹配，注意**相邻性问题**（如"化学工程"不能匹配"化 学 工 程"中的"化工"）
- 优先放长关键词（如 `'道路桥梁'` 在 `'道路'` 之前）
- 每次新增专业若走到兜底，必须评估是否应加关键词

**禁止模式（检测即修复）：**
- ❌ `"X是研究X相关理论与实践的专业，培养掌握X基本理论知识和实践技能的专业人才"`（模板套话）
- ❌ overview 以其他专业名开头（如"建筑学是研究…"出现在化学工程专业）
- ❌ `"培养具备工程技术能力和实践经验的专门人才"`（旧版兜底，已废弃）

### 2.2 `what_you_learn` — 学习内容

```
格式: "1）理论基础：{课程1}、{课程2}、…；2）分析方法：{课程1}、…；3）应用领域：{课程1}、…；核心能力：{能力1}、{能力2}、…。"
长度: 100-250字
```

- 课程必须从 `KB[catCode].courses` 或 `SUBCAT_COURSES[subKey]` 提取
- 默认课程表按大一~大四分为4组，每年3-6门
- 不能臆造课程名；未知课程用"专业核心课1"比编造假名更诚实

### 2.3 `suitable_for` — 适合人群

```
格式: "{专业名}适合以下学生：1）{特质1}；2）{特质2}；…；5）{特质5}。慎报情况：{反指标}的学生慎报。"
长度: 100-250字
```

- 必须含 3-5 条"适合"和 1-2 条"慎报"
- 使用 `KB[catCode].suitable(major)` 生成

### 2.4 `career_outlook` — 就业前景

```
格式: 三层金字塔描述 — "塔尖（约X%）：{雇主}，年薪X-Y万；塔身（约X%）：{雇主}，年薪X-Y万；塔基（约X%）：{雇主}，年薪X-Y万。"
长度: 150-400字
```

- 薪资用**年薪万**为单位（与 salary_range 的月薪k区分）
- 必须给出具体的雇主/行业名称，不能泛泛而谈

### 2.5 `xuefeng_comment` — 张雪峰风格点评

```
格式: Markdown 多段落，含加粗、列表
长度: 350-500字
```

**8大学科模板体系：**

| 模板 | 门类 | 核心论点 |
|------|------|---------|
| 文科 | 01/03/04/05/06 | 考公/教师/综合素质 |
| 经管 | 02/12 | 上限高下限低/名校出身/考证 |
| 理学 | 07 | 基础学科/需深造/万金油 |
| 工学 | 08(非IT) | 就业好但苦/技术积累 |
| 计算机 | 08(IT类) | 热门高薪/35岁/持续学习 |
| 农学 | 09 | 冷门刚需/国家扶持 |
| 艺术 | 13 | 烧钱/天赋/两极分化 |
| 医学 | 10 | 长学制/稳定高收入 |

- IT专业检测规则：`KB['08'].isIT(major)` — 名称含 `['计算机','软件','网络','信息安全','物联网','数字媒体','智能科学','数据科学','大数据','网络空间','新媒体','虚拟现实','区块链','密码','工业软件','人工智能','电影制作','保密技术','服务科学','空间信息']`
- 每个专业必须在模板基础上加入 2-3 句**该专业特有的内容**

### 2.6 `yearly_courses` — 逐年课程

```
格式: JSON {"大一":["课1","课2",...], "大二":[...], "大三":[...], "大四":[...]}
键名: 大一、大二、大三、大四、大五（仅医学类）
每年课程数: 3-6门
```

**课程命名规则：**
- 使用中国大陆高校通用课程名
- 区分上下学期：`高等数学(上)` / `高等数学(下)`
- 专业课程名称遵循教育部学科目录规范
- 禁止臆造不存在的课程名

### 2.7 `top_universities` — 推荐院校

```
格式: JSON {"domestic":["校名1",...], "international":["校名1",...]}
各5所
```

- 国内：优先985/211/双一流学科院校
- 国际：QS/THE排名前列 + 该领域公认强校
- 来源：`KB[catCode].unis`

### 2.8 `difficulty` — 学习难度

```
格式: ⭐ (1-5颗星)
```

| 星数 | 门类 |
|------|------|
| ⭐⭐⭐⭐⭐ | 10医学, 14交叉学科 |
| ⭐⭐⭐⭐ | 01哲学, 02经济学, 03法学, 07理学, 08工学 |
| ⭐⭐⭐ | 04教育学, 05文学, 06历史学, 09农学, 12管理学, 13艺术学 |

- IT/CS专业：4星（`KB['08'].difficulty_IT`）
- 5年制专业（建筑学、临床医学等）：5星

### 2.10 `degree` — 学位

```
格式: "{学科}学士"   示例: 工学学士
```

- 优先使用 `moe_2026_reference.degree`
- 否则按门类默认：`CAT_DEGREE[catCode]`
- 复合学位（如"工学或理学学士"）需用 `expandDegree()` 展开

### 2.11 `duration` — 学制

```
格式: 整数 4 或 5
```

- 默认 4 年
- 5 年制：临床医学类(1002/1003/1005/1006)、口腔医学(1003)、建筑学(0828)、城乡规划(082802)、风景园林(082803)、动物医学(0904)、法医学(1009)、预防医学(1004)、中医学类等
- **注意：`duration` 列是 INTEGER 类型，不能传 `"4年"` 字符串**

### 2.12 `career_directions` — 就业方向

```
格式: JSON 字符串数组 ["方向1", "方向2", ...]
数量: 3-6个
```

- 来源：`CAT_CAREERS[catCode]`（在 `fill-factual-fields.js` 中定义）

## 三、KB（知识库）架构规范

### 3.1 文件位置

```
scripts/data/knowledge-base.js
```

### 3.2 每个门类条目结构

```js
'XX': {
  name: '门类名',
  overview: (major) => {...},    // 必须：专业概述函数
  difficulty: Number,             // 必须：默认难度(1-5)
  salary: '¥Xk-Yk',              // 必须：默认薪资
  courses: { '大一':[], ... },    // 必须：默认课程
  careers: { tiers:'...', employers:[...] },  // 必须
  unis: { domestic:[...], international:[...] }, // 必须
  suitable: (major) => {...},    // 必须
  xuefeng: (major) => {...},     // 必须
}
```

### 3.3 扩展规则

当需要为特定门类内子类添加特殊处理时，挂载到 `KB[catCode]` 上：

```js
// IT类特殊处理示例
KB['08'].isIT = (major) => { ... };          // 判断函数
KB['08'].overview_IT = (major) => { ... };   // 专用overview
KB['08'].xuefeng_IT = (major) => { ... };    // 专用点评
KB['08'].salary_IT = '¥10k-35k';             // 专用薪资
KB['08'].difficulty_IT = 4;                  // 专用难度
```

### 3.4 关键词添加流程

当发现某专业走到兜底（generic fallback）时：
1. 检查其专业名是否已被现有关键词覆盖（注意 `includes` 的相邻性问题）
2. 若未覆盖，在对应门类的 `overview` 函数的 `map` 中添加新条目
3. 关键词按**具体性**排序：长词在前，短词在后
4. 写描述时参考该专业的真实学科内容，不要抄其他专业的描述
5. 添加后重跑 fix 脚本验证

## 四、生成与修复脚本体系

### 4.1 执行顺序

```
Phase 1: fill-factual-fields.js
  ↓  填充 degree, duration, career_directions（从 MOE 参考表 + 门类默认值）
  
Phase 2: generate-content.js  
  ↓  为 EMPTY 专业生成全部内容字段（从 KB 模板）
  ↓  注意：只处理 overview 为空的条目，不覆盖已有内容
  
Phase 3: normalize-formats.js
  ↓  标准化 difficulty→⭐, salary→¥Xk-Yk, yearly_courses键名→中文
  ↓  填补缺失的 yearly_courses

Quality Fix: fix-bad-overviews.js
  ↓  检测并修复：模板套话、张冠李戴、¥0k-0k薪资、旧版兜底
```

### 4.2 关键注意事项

**Supabase REST API：**
- 所有请求头必须含 `apikey` 和 `Authorization: Bearer {KEY}`
- PATCH 时加 `Prefer: return=minimal` 避免返回数据
- 分页：`limit=1000&offset=N`，REST API 默认最多返回 1000 行
- **绝对不要用 `URL` 作为变量名**（会覆盖全局 `URL` 构造函数）

**`duration` 列陷阱：**
- 该列类型是 **INTEGER**，必须传数字 `4` 或 `5`
- 传字符串 `"4年"` 会导致 `invalid input syntax for type integer`

**yearly_courses JSON 陷阱：**
- 必须是解析后的 JSON 对象，不能是 JSON 字符串
- 如果数据库中存的是字符串（数字键 0,1,2...），需要 `JSON.parse()` 后再 PATCH
- 键名必须是中文：大一、大二、大三、大四、大五

### 4.3 调试技巧

```bash
# 快速查 Supabase 行数
curl -s "{URL}/rest/v1/majors?select=count" -H "Prefer: count=exact" -H "apikey: {KEY}"

# 查特定条目
curl -s "{URL}/rest/v1/majors?select=code,name,overview,salary_range&code=eq.{CODE}" -H "apikey: {KEY}"

# 用 Node 做数据分析
node -e "const data = require('./temp_full_data.json'); ..."
```

## 五、质量验证检查清单

- [ ] `majors` 表总数 = `moe_2026_reference` 表总数（当前：883）
- [ ] 所有条目 12 个内容字段均不为 null
- [ ] `salary_range` 全部匹配 `¥\d+k-\d+k` 正则

## 七、深度分析报告 — 系统架构

### 7.1 两条生成路径

| 路径 | 引擎 | 触发方式 | 适用场景 |
|------|------|---------|---------|
| **生产路径** | Supabase Edge Function → DeepSeek API | 管理后台一键生成 | 单份报告实时生成 |
| **批量路径** | Python 脚本 → DeepSeek API | CLI 命令行 | 批量预生成 |

### 7.2 核心文件

| 文件 | 职责 |
|------|------|
| `supabase/functions/generate-report/index.ts` | **主生成引擎**：Deno Edge Function，构建 prompt + 调 DeepSeek + 验证 + 生成预览 |
| `js/pages/admin-reports.js` | 管理后台：触发生成、编辑、发布、删除 |
| `js/reports.js` | 前端 API：获取报告列表、解锁、检查已解锁 |
| `js/pages/reports-page.js` | 用户端：浏览报告、解锁阅读 |
| `scripts/batch_generate.py` | Python 批量生成脚本（旧版 8 章结构） |
| `utils/api_client.py` | LLM 客户端抽象层（DeepSeek/OpenAI/Anthropic/百度） |
| `sql/supabase-init.sql` | `reports` 表 DDL |
| `sql/add-spend-points-function.sql` | 原子化点数消费函数 `spend_points()` |

### 7.3 数据库存储

**`reports` 表结构：**

| 列 | 类型 | 说明 |
|------|------|------|
| `id` | UUID PK | 自动生成 |
| `major_code` | VARCHAR(10) UNIQUE | 与 majors 表对应 |
| `major_name` | VARCHAR(100) | 专业名称 |
| `category` | VARCHAR(50) | 学科门类 |
| `preview_content` | TEXT | 预览摘要（HTML） |
| `full_content` | TEXT | 完整报告（HTML，~10000字） |
| `status` | VARCHAR(20) | published / draft / archived |
| `download_count` | INTEGER | 解锁次数 |
| `created_at` / `updated_at` | TIMESTAMPTZ | 时间戳 |

**关联表 `download_records`：** 记录用户解锁（user_id + report_id + points_spent + timestamp）

## 八、报告结构 — 13 章模板

### 8.1 完整章节树

```
<h1>{专业名} — 深度分析报告</h1>

<h2>一、专业概述</h2>
  1.1 专业定义与学科定位（150-200字）
  1.2 培养目标（3-5条）
  1.3 学科特点与核心价值（3-4个特点）

<h2>二、课程安排与学习内容</h2>
  2.1 分年级课程体系（HTML表格：大一~大四）
  2.2 核心课程详解（3-5门，每门50-80字）
  2.3 实践教学环节（5-6项）
  2.4 核心能力培养（4-5项）

<h2>三、就业前景分析</h2>
  3.1 就业率数据（总体/对口/满意度，标注来源）
  3.2 主要就业方向（7-10个，分"核心技术岗"和"拓展方向"）
  3.3 行业分布（6个以上行业+大致百分比）
  3.4 绿牌/红牌标识及解读

<h2>四、薪资水平与职业发展</h2>
  4.1 薪资数据（应届/3年/5年/10年平均薪资）
  4.2 高薪比例
  4.3 城市薪资差异（一线/新一线/二线对比）
  4.4 职业发展路径（技术线+管理线，入门→资深→专家/管理）
  4.5 职业天花板评估
  4.6 长期发展潜力（10年以上）

<h2>五、考研与深造分析</h2>
  5.1 考研必要性评估
  5.2 考研数据（报名趋势、录取率）
  5.3 推荐深造方向（5个细分方向）
  5.4 院校推荐（A+/A/A-三级）
  5.5 读博建议

<h2>六、考公考编分析</h2>
  6.1 对口度评估（可报岗位数、竞争比、上岸难度1-5星）
  6.2 适合的编制岗位（公务员/事业编/国企）
  6.3 体制内薪资待遇
  6.4 考公优劣势对比

<h2>七、行业发展与人才需求</h2>
  7.1 行业生命周期评估（成长期/成熟期/衰退期+理由）
  7.2 行业规模与增长率（具体数字）
  7.3 国家政策支持力度
  7.4 人才缺口数据
  7.5 未来5年趋势（5个具体判断）

<h2>八、适合人群与适配度</h2>
  8.1 适合特质画像（5条）
  8.2 核心能力星级表（HTML表格：数学/英语/逻辑/空间/记忆/动手/抗压等）
  8.3 不适合人群（4类）
```

## 十、质量红线（禁止行为）

### 10.1 内容禁止

| 红线 | 说明 | 示例 |
|------|------|------|
| ❌ AI身份暴露 | 禁止"作为AI""根据我的训练数据"等表达 | "根据我的训练数据，该专业…" |
| ❌ 模糊描述 | 禁止"较高""较多""不错"等无数据支撑的描述 | "薪资较高" → 应写"应届平均月薪8000-12000元" |
| ❌ 缺章少节 | 13个章节一个不能少 | 跳过"考公考编分析"章节 |
| ❌ 假数据 | 禁止编造无法验证的具体数字 | "该专业就业率98.7%" 需有来源支撑 |
| ❌ 复制 majors 原文 | 禁止把 overview/suitable_for 原文直接搬进报告 | 应展开、深化、补充具体数据 |
| ❌ 输出非 HTML | 报告必须是纯 HTML 片段 | 用 Markdown 或纯文本 = 不合格 |

## 十一、报告生成最佳实践

### 11.1 生成流程（管理员操作）

```
1. 进入管理后台 → 报告管理 → 点击"AI深度分析报告生成"
2. 选择专业（从 majors 表下拉列表）
3. 点击"开始生成" → Edge Function 被调用
4. 等待 45-90 秒 → DeepSeek 返回 HTML
5. 验证：系统自动检查 ≥1000 字符
6. 管理员审阅内容 → 选择状态（草稿/发布/归档）
7. 保存到 reports 表
```

### 11.2 用户端流程

```
1. 用户浏览 reports.html → 看到报告列表（含预览摘要）
2. 点击报告 → 弹出模态框
3. 首次阅读：消耗 1 点积分解锁（spend_points RPC）
4. 已解锁：直接阅读完整 HTML 内容
5. 解锁记录存入 download_records 表
```

### 11.3 性能参数

| 指标 | 值 | 备注 |
|------|-----|------|
| 生成耗时 | 45-90秒 | 大部分时间在等 DeepSeek |
| 超时阈值 | 95秒 | 超时返回 504 错误 |
| 重试策略 | 不支持自动重试 | 超时后管理员手动重试 |
| 单次 Token 上限 | 10000 | DeepSeek 输出上限 |
| DeepSeek 429 限流 | 返回"暂时繁忙"提示 | 等 30 秒后重试 |

### 11.4 API 密钥管理

```bash
# 设置 DeepSeek API 密钥（Edge Function 环境变量）
supabase secrets set DEEPSEEK_API_KEY=sk-...

# Edge Function 运行时通过 Deno.env.get() 读取
const apiKey = Deno.env.get("DEEPSEEK_API_KEY");
```

### 11.5 与 majors 表内容的边界

| 在 majors 表中 | 在 reports 中 |
|---------------|--------------|
| 概述模板（40-200字） | 展开为 150-200字的 1.1 专业定义 + 1.2 培养目标 |
| 薪资字段（`¥8k-28k`） | 展开为 4.1-4.6 六个子节的详实数据 |
| 就业方向数组（3-6项） | 展开为 3.2 十大就业方向 + 3.3 行业分布 |
| 雪峰点评模板（350-500字） | 展开为 13.1-13.4 四段式完整点评 |
| 适合人群（100-250字） | 展开为 8.1-8.4 含能力星级表和性别分析 |

**核心原则：majors 表提供"骨架"，reports 提供"血肉"。报告必须比 majors 数据深入 3-5 倍。**
